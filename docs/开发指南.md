# 开发指南

## 生成过程

`scripts/build.cjs` 读取模板、页面、样式及各脚本，生成 `app/index.html`。程序仍以单个 HTML 运行，保留原来的桌面协议和行为。

启动和打包前的 `scripts/prepare-app.cjs` 还会确认 Electron 运行包已准备好。Electron 45 在首次使用时下载运行包，因此不要求先手动启动一次工具再打包。

`src/editor.js` 中的 `/*__IO_ALARM_RUNTIME__*/` 是构建插入位置，实际内容来自 `src/io-alarm.js`。模板中的 `@@...@@` 也由构建脚本替换，不要删除这些标记。

第三方 html2canvas 保留在 `vendor/`，许可说明在 `licenses/`。

## 页面和样式

- 例如 `config-alarm-base.html` 是整个 Alarm Base 页面，`base_alarm_io` 是其中的 IO Alarm 区域。
- 公共主题在 `styles/theme.css`；模块 CSS、模块框架和顶部导航由资源映射指定。
- 新增源码页面后，需要在 `project.json` 的 `project.pages` 和 `files.content` 中登记。通过 EXE 新建并保存工程，再导入源码，通常更方便。
- 工具导出的工程 JSON 与源码的资源映射 JSON 格式不同，不能直接相互覆盖。请使用 `npm run import-project -- 文件路径`。

## 工程导入和回退

导入脚本只接受本工具“保存工程”生成的 JSON，先校验页面与资源，再备份原 `src/prototype/`，最后更新资源映射。它不导入浏览器或 EXE 的个人预览缓存。

备份路径会在命令结束后显示，位于 `.qa/backups/`。需要回退时，把备份中的原型文件恢复到 `src/prototype/`，然后重新构建。导入后未使用的旧文件可能仍在目录内，构建内容由新资源映射决定。

## 交互和数据

- 设计态 `store` 与预览态 `previewData` 分开维护。
- 通用表单和滑块逻辑主要在 `src/editor.js` 的 `wirePrototypeControls`。
- IO Alarm 逻辑在 `src/io-alarm.js`。页面里的 `data-io-details` 保存各路 Sensor 状态，`data-io-defaults` 保存导入默认值。
- Server 动态页签、不同 Sensor 的可变数据应独立复制；复制控件时保留引用关系并避免重复 ID。
- 修改交互后，检查编辑、预览、保存重开及导出 HTML 四条路径。

## 桌面程序

`app/main.cjs` 管理窗口、本地协议和 PNG 保存；`preload.cjs` 只开放受限接口；`png-files.cjs` 负责文件名和 PNG 校验。保留 sandbox、contextIsolation 和现有来源检查。

开发启动使用项目下 `.dev-profile`。正式 EXE 使用 `%APPDATA%/PrototypeEditor-Desktop`。测试和分享源码时不要带上个人数据目录。

## 检查范围

`npm run check` 不依赖第三方测试库，可检查源文件、页面映射和生成脚本语法。`npm test` 需要先安装依赖，覆盖工程导入备份、原页面基线、不同 Uses 的字段、Sensor 独立数据、Cancel、数值限制、Save、Default、导出及字体颜色。

测试结果位于 `.qa/`。页面默认值或结构主动变化后，按新需求调整 `tests/fixtures/`；不要仅为通过测试而删掉检查。自动检查不替代最终 EXE 的实际显示和交互验收。

## 构建问题

- 依赖或下载失败：检查 Node 版本、网络及 npm 日志，依赖版本由锁文件固定。
- `npm start` 只激活旧窗口：关闭旧版，再确认使用独立开发数据目录。
- 修改后没有效果：确认修改的是 `src/`，再执行 `npm run build`。
- 单文件打包失败：先运行 `npm run pack` 检查目录版，再根据便携封装日志排查。无需通过关闭系统安全保护解决。
- 目录版 EXE 不能单独拷贝：它依赖同目录的运行文件；单文件分享使用便携版产物。

第三方许可文件保留在 `licenses/` 和原有资源注释中。
